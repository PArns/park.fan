# Parks we cannot read (REQUIREMENT)

One standing rule. It is indexed from the repo's [`CLAUDE.md`](../../CLAUDE.md), which carries the rule in one line and links here for the reasoning, the measurements and the counter-examples.

Hansa-Park publishes wait times only in its own app on the park WLAN, so no number will ever arrive for it — and a park with no source is **indistinguishable from a park shut for the night** in the payload (at 03:00 every park has zero rides operating and empty `queues`). So never derive it: the API's curated `liveWaitTimes` (`{available, reason}`) is the only signal, read through `noLiveWaitTimesReason()` / `hasReadableWaitTimes()` in `lib/utils/live-wait-times.ts`, which treats an absent field as available so older/cached responses keep behaving as before. It is **not** a freshness check — a feed that went quiet an hour ago stays `available: true`. Left alone, the page fills the gap with the shape of a quiet park: 82 of 82 rides "running" at `very_low`, Ø 0 min, plus an ML forecast built on zero observations. Crowd badges need no special case (the API sends `unknown` → "keine Prognose"); the listing surfaces **strip** `crowdLevel`/`averageWaitTime`/`operatingAttractions` at the projection boundary rather than shipping the flag, because the poll re-downloads its nine fields per park every 5 min and this one never changes. And the two surfaces that say so out loud — the notice and the overview's summary line — carry **`data-nosnippet`**, as prevention rather than repair: they are the most quotable prose on the strongest page the site has, and a result answering „Hansa-Park Wartezeiten" with „Keine Wartezeiten verfügbar" is a result nobody clicks. Google is **not** doing that — checked 2026-08-30, the head query renders the meta description verbatim — but a snippet is picked per query, so the guard is cheap and the alternative is not: `noindex` has no per-element form and the page-level one would drop the park, while `data-nosnippet` keeps the sentence crawled, ranked and visible to the reader and only bars it from the description. Honoured on `div`/`span`/`section` alone, which is why the summary line wraps a `<span>` rather than tagging its `<p>`. Two things it does not touch, both in that same result: title, meta description and the FAQ still promise live wait times there (a ranking decision on the biggest page), and the „vor 6 Tagen" in front of the snippet is the page dating **itself** — „Heute, Sonntag, 30. August 2026, hat der Hansa-Park … geöffnet" stands in the FAQ block and again in the FAQPage JSON-LD, there is no `datePublished`/`dateModified`, so Google shows what it read on its last crawl. See [parks without wait times](docs/api/parks-without-wait-times.md).
