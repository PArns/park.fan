# A streamed section owes the page its height (REQUIREMENT)

One standing rule. It is indexed from the repo's [`CLAUDE.md`](../../CLAUDE.md), which carries the rule in one line and links here for the reasoning, the measurements and the counter-examples.

the park page buys TTFB by streaming its slow parts, and the bill arrives as CLS — charged to whatever the visitor is looking at when the boundary resolves. So a `<Suspense>` fallback must reserve the height its content will take. `fallback={null}` is honest only when nothing renders below it: the blog section had one and did **no async work at all** (`hasPublishedPosts`/`getPostsForPark` read the generated manifest synchronously, the lone `await getTranslations` hits messages the render already holds), so the boundary deferred nothing and dropped 467 px of content out of thin air — synchronous data belongs inline, in the first HTML, at full height. And a fallback should render whatever needs **no** data rather than a grey box shaped like it: the best-days header is data-free and its height depends on how the park name wraps (one line on desktop, two on a phone), which sized `Skeleton` blocks were 66–120 px short of until the fallback started rendering the real `ParkBestDaysHeader`. Measure the three states a visitor can observe — fallback, server seed, settled queries — and diff the block geometry; that delta _is_ the shift, and seed → settled measures 0, so the client queries were never it. And on a **prerendered** route a boundary defers nothing whatsoever: the project runs no PPR, so the prerender waits for it anyway and the resolved markup already sits in the shipped `.html`, sorted to the end of the byte stream in a `<div hidden id="S:1">` and grafted in by the `$RC()` after it — which is how the glossary term page dropped 396–1463 px into the column two seconds after paint and pushed the "back to dictionary" button (`div.pb-2`, the element Cloudflare names) down with everything under it. The client side has the same shape: **reserve the outcome most visitors get rather than nothing** — `FavoritesSection` rendered `null` until it could read the cookie and then a 232 px band arrived out of nowhere on the homepage, all five blog routes and every glossary term, so the pre-mount branch now holds the empty state's box with its two lines `invisible`. And **two states that never coexist still need one height**: the coaster player's 57 px transport bar hung on `ready && !failed`, so it appeared when three.js booted on all 42 term pages that have one. Two gaps are left on purpose: the school-holiday warning (data-dependent, on 6 of 27 sampled parks) and `NearbyParksSection`, because **48 % of the 212 parks render no nearby section at all**, so a fixed reservation would collapse ~500 px on half the catalog — the same reason the glossary rides section got no padded fallback, since 115 of 267 terms have no rides. **The geometry may not depend on data, the content may:** the header's "Auslastung heute" metric only rendered once it had a value, and every input that could decide that lands after the first paint (`crowdToday.level` from the page's deliberately last query, `isOpenish` from `liveStatus ?? scheduledStatus ?? status`), so the band moved 340 → 419 px at 2059 ms on a park that gets a rating and 63 → 142 → 63 px on one that does not. It is unconditional now, like `crowdNow` beside it, with a badge, a loading pill or an em dash inside the same reserved box. A placeholder's height is **measured off the real thing, per breakpoint** — `ParkCard` hides its photo row below `sm` and is 146 px there against 366, so one 360 px placeholder over-reserved a phone by 2.4× and the featured grid collapsed 1284 px — and it has to match the real thing's **tags** too, because the diff pairs children by tag once their classes differ. **A score is a fact about a reader position, not about a page** — `--late` prints the `y=` it measured at on every line, because from `y=0` alone three park pages Cloudflare scores 0.98 came back 0.0001, 0.0002 and 0.0002, the block that grows sitting four screens below the first one; it now measures the top and just under the biggest growth (1.3421 on Islands of Adventure at `y=3346`), and says so in words when nothing scored at any position it tried. **Proving a fix needs `pnpm measure:cls --late`**, not CPU throttling: the same page under the same 4× throttle measured 0.000 and 0.088 in two consecutive runs, while `--late` (shell now, streamed tail 1.5 s later, nothing throttled) reproduces Cloudflare's 0.538 for the glossary page to within 0.005, every run. The harness also sends a real `x-forwarded-for` now: from 127.0.0.1 `/api/nearby` geolocates nothing and every run settled on the nearby card's short empty state, which is how its placeholder got tuned backwards by 683 px. **And it is measured against `pnpm build && pnpm start`, at `localhost`** — both halves, because a run against `next dev` or against `127.0.0.1` reports a confident 0.0000 and looks exactly like a page with nothing wrong. `next dev` injects the stylesheet through JavaScript, so the JS-off pass (this script's whole model of the first paint) renders **unstyled** markup and every row it prints is Tailwind that had not arrived — one park page came out 8695 px "first" against 4408 px settled. And `next dev` answers **403** for `/_next/static/chunks/*` when the origin is `127.0.0.1`, which was the script's own default base: every chunk fails, the page never hydrates, and three consecutive runs graded a park page with no client JavaScript in it at all. Both are now refused rather than graded — `assertMeasurable` aborts on a failed `/_next/` subresource and on a JS-off body still sitting in the browser's serif default — and the default base is `localhost`. Two more things the dev server cannot show you: it flushes the whole document in one go, so every Suspense boundary resolves before the first paint, and its API responses are not the ones a phone waits on.
