Inventory of the host repository taken on 2026-09-05 (commit `f0c2754`), and the one line per
convention that the game adopts. Every deviation carries its reason. Nothing in this document is
aspirational: it is what the repo does today, verified by reading the files named.

## 2. What the game adopts (one line each)

- **Route**: `app/game/**` — a non-localized route folder outside `app/[locale]`, exactly like `app/admin`. `page.tsx` is a Server Component (metadata, loading shell); the canvas is a Client Component behind `next/dynamic(..., { ssr: false })`.
- **Feature root**: `lib/game/**` — one folder per subsystem (`core`, `terrain`, `environment`, `ui`, …), the same place the repo keeps its other engines (`lib/three/`, `lib/planner/`).
- **React UI of the game**: inside the feature root (`lib/game/ui/**` and each module's own `*.tsx`), built from `@/components/ui/*`, `GlassCard`, `Badge`, `Button`, Lucide icons and the glass recipes. No second component library.
- **Styling**: Tailwind v4 utilities and the existing tokens. Game-specific tokens are added as `--game-*` custom properties in `lib/game/ui/game.css`, imported only by `app/game/layout.tsx`, and exposed to Tailwind through the same `@theme inline` mechanism — never a second Tailwind config.
- **Dark theme**: the game route hardcodes `className="dark"` on `<html>`, like `/admin`, because the world is rendered for a dark HUD and the HUD is glass over a 3D scene.
- **Fonts**: Geist through `next/font/google`, same variable name.
- **TypeScript**: strict, `@/` alias, no new tsconfig.
- **Lint/format**: the existing ESLint + Prettier; `pnpm lint` and `pnpm format:check` must stay green.
- **Tests**: `scripts/test-game-*.mjs` under `node --experimental-strip-types` with `pnpm test:game-*` scripts; browser harnesses `scripts/game-shot.mjs`, `scripts/game-warm-audit.mjs` and `scripts/game-exposure-curve.mjs` follow `measure-cls.mjs` (Playwright, container Chromium, `next build && next start` at `localhost`); `scripts/game-soak.mjs` and `scripts/game-day-budget.mjs` need no browser at all — `SimRuntime` is import-safe under node, which is what lets a whole park day be measured without a canvas.
- **A screenshot of this game is taken with a stopped clock, and that hides working features.** The
  shot harness runs at `speed=0` so a frame is repeatable, so anything that accumulates over park
  minutes is at its zero: the park has **no guests**, `environment.wetness` is **0** (the paving
  keeps its dry `albedoColor` 1 / `roughness` 1), and three of the seven shops have not opened. Use
  `--step=<ticks>` for any of that, and `--particles=<seconds per frame>` for a particle effect —
  Babylon ages a particle by the REAL frame delta, and SwiftShader's is longer than a raindrop
  lives. `pnpm game:warm-audit` walks every module's `stats()` at tick 0 and again after 30 and 120
  park minutes and prints what moved, which is how the next one gets found by a script rather than
  by somebody wondering why the rain looks wrong.
- **Feature flags**: `NEXT_PUBLIC_GAME_SHARING` and `NEXT_PUBLIC_GAME_LIVE_SEED` via `envFlag()` in `lib/config/features.ts` (additive entries).
- **Persistence**: IndexedDB on the client, JSON export/import. The optional blueprint-sharing Route Handler sits under `app/api/game/**` and is gated by the flag.
- **Assets**: `public/game/assets/**`, fetched by `scripts/fetch-game-assets.mjs`, gitignored, provenance in `docs/game/ASSETS.md`; long-cache headers as an additive `headers()` entry.
- **Docs**: `docs/game/*.md`, linked from `docs/README.md`.
- **Git**: feature branch `claude/park-coaster-game-integration-5bmp34`, commit messages in the repo's style (German subject lines are the norm; English is fine and used here).

## 3. Deviations, with reasons

| Deviation                                                             | Reason                                                                                                                                                                                                                                                                                                                                                                              |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Game UI strings do **not** live in `messages/*.json`                  | `/game` is outside `app/[locale]`, so the routed-messages machinery (`RouteMessages`, the generated namespace map, `check:client-messages`) does not apply — the same reason `/admin` gives. Strings live in `lib/game/i18n/<locale>.ts` (EN complete, DE complete, the other four fall back to EN), resolved once from the `NEXT_LOCALE` cookie / `Accept-Language` in the layout. |
| One additive edit to `proxy.ts`                                       | The matcher's negative lookahead must list `game` next to `admin` and `dev`, or next-intl redirects `/game` to `/de/game`.                                                                                                                                                                                                                                                          |
| No Havok                                                              | Coaster and guest physics are deterministic, energy-based and run in the worker; a WASM rigid-body engine is neither needed nor deterministic across builds. Removes a 2 MB WASM download. See `DECISIONS.md`.                                                                                                                                                                      |
| React components inside `lib/game/**` instead of `components/game/**` | The brief asks for one feature folder; the repo's own `app/admin/_ui` precedent shows a feature keeping its UI beside its logic. Shared UI is still imported from `@/components/ui`.                                                                                                                                                                                                |
| `three` is not reused                                                 | The brief specifies Babylon.js. The three.js coaster player stays where it is; the two do not share code. The glossary's coaster element data (`lib/three/coaster/elements.ts`) is a reference for track vocabulary, not a dependency.                                                                                                                                              |
