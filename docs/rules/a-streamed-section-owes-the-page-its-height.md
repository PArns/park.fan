# A streamed section owes the page its height (REQUIREMENT)

One standing rule. It is indexed from the repo's [`CLAUDE.md`](../../CLAUDE.md), which carries the rule in one line and links here for the reasoning, the measurements and the counter-examples.

the park page buys TTFB by streaming its slow parts, and the bill arrives as CLS — charged to whatever the visitor is looking at when the boundary resolves. So a `<Suspense>` fallback must reserve the height its content will take. `fallback={null}` is honest only when nothing renders below it: the blog section had one and did **no async work at all** (`hasPublishedPosts`/`getPostsForPark` read the generated manifest synchronously, the lone `await getTranslations` hits messages the render already holds), so the boundary deferred nothing and dropped 467 px of content out of thin air — synchronous data belongs inline, in the first HTML, at full height. And a fallback should render whatever needs **no** data rather than a grey box shaped like it: the best-days header is data-free and its height depends on how the park name wraps (one line on desktop, two on a phone), which sized `Skeleton` blocks were 66–120 px short of until the fallback started rendering the real `ParkBestDaysHeader`. Measure the three states a visitor can observe — fallback, server seed, settled queries — and diff the block geometry; that delta _is_ the shift, and seed → settled measures 0, so the client queries were never it. And on a **prerendered** route a boundary defers nothing whatsoever: the project runs no PPR, so the prerender waits for it anyway and the resolved markup already sits in the shipped `.html`, sorted to the end of the byte stream in a `<div hidden id="S:1">` and grafted in by the `$RC()` after it — which is how the glossary term page dropped 396–1463 px into the column two seconds after paint and pushed the "back to dictionary" button (`div.pb-2`, the element Cloudflare names) down with everything under it. The client side has the same shape: **reserve the outcome most visitors get rather than nothing** — `FavoritesSection` rendered `null` until it could read the cookie and then a 232 px band arrived out of nowhere on the homepage, all five blog routes and every glossary term, so the pre-mount branch now holds the empty state's box with its two lines `invisible`. And **two states that never coexist still need one height**: the coaster player's 57 px transport bar hung on `ready && !failed`, so it appeared when three.js booted on all 42 term pages that have one. One gap is left on purpose: `NearbyParksSection`, because **48 % of the 212 parks render no nearby section at all**, so a fixed reservation would collapse ~500 px on half the catalog — the same reason the glossary rides section got no padded fallback, since 115 of 267 terms have no rides. The school-holiday warning used to be listed beside it and is no longer a gap of any kind, because it does not shift: `ParkHolidayRow` reads `initialData.schedule`, which `leanParkForShell` keeps whole, and all 210 parks the API serves answer with `schedule[0].date` equal to today in their own timezone, holiday flags included — so the entry `useTodaySchedule` falls back to before the clock mounts is the entry it picks after, and the band is in the first HTML at full height (Lotte World Adventure on a bridge day: 96 px with JavaScript off, 96 px settled, same chips). **A strip that is never in the first HTML is the opposite case: it holds a box, or it goes where a box already is.** The park page's rain/storm nowcast is fetched client-side by construction (`useWeatherNowcast` is `enabled: typeof window !== 'undefined'`, and the page seeds `initialData={null}` so a slow nowcast cannot poison the render), so on the 11 of 210 parks that had an alert on 2026-09-21 it landed 2.5 s after paint and pushed the page down by 134 px, which cost a reader parked at `y=1300` on a phone 0.1476. The first fix held the box: the wrapper in `park-today-panel.tsx` reserved 135 px below `sm` and 104 px from `sm` up, measured off the real strip. It removed the shift and put a band of nothing across the middle of the header card on the 94.8 % of parks with no alert, all day, which is what a reader saw. The second fix puts the warning where a box already is. The panel's title row is on every park at a fixed 45 px, so `useNowcastAlert` (the banner's query, clock and wording, without the box) is said there as one line, `NowcastAlertToggle`, in the slot the weather reading holds, and the full `NowcastAlertBanner` opens under the row only on a press. A late warning changes the row's text and not its height (45 px at 360, 390, 640, 700, 1024 and 1280 px, with and without a rain, thunderstorm and storm warning), and a shift within 500 ms of the visitor's own input is not a layout shift (`hadRecentInput`). The toggle is `-my-[3px]` against its own `py-0.5` and border for that reason: one pixel taller than the row's `text-sm` line and the row would grow the moment the nowcast landed. Below `sm` the heading and the clock give way to the warning; beside them it had about 120 px and cut „Gewitter in ca. 25 Min." off before the minutes. **The geometry may not depend on data, the content may:** the header's "Auslastung heute" metric only rendered once it had a value, and every input that could decide that lands after the first paint (`crowdToday.level` from the page's deliberately last query, `isOpenish` from `liveStatus ?? scheduledStatus ?? status`), so the band moved 340 → 419 px at 2059 ms on a park that gets a rating and 63 → 142 → 63 px on one that does not. It is unconditional now, like `crowdNow` beside it, with a badge, a loading pill or an em dash inside the same reserved box. The same holds for **how** a cell lays out, not only whether it renders: `crowdNow` and `forecastToday` sat in a `flex-wrap` row, so side by side or stacked was decided by the width of the two values, and the forecast turns from an 80 px loading pill into a badge with a chevron at ~4.4 s — on Phantasialand at 1280 px that tipped the pair from one row to two and moved the card 16 px. They are stacked at every width now. **A web font is late content too:** Geist is `display: swap`, so a first visit paints in „Geist Fallback" and re-lays out when Geist lands (~440 ms). A label that sits at a wrap edge changes its line count across that swap — „Wartezeiten-Kalender" is one line in the fallback and two in Geist, which grew the park tile row 132 → 148 px in de and nl at 390, 1280 and 1440 px and in es at 800 px. The row now holds two lines for every label (`ParkTileGrid`). Reproduce it by holding the `.woff2` back with a Playwright route and diffing the geometry before and after release. A placeholder's height is **measured off the real thing, per breakpoint** — `ParkCard` hid its photo row below `sm` and was 146 px there against 366 (a 100 px row since PAR-432), so one 360 px placeholder over-reserved a phone by 2.4× and the featured grid collapsed 1284 px — and it has to match the real thing's **tags** too, because the diff pairs children by tag once their classes differ. **A score is a fact about a reader position, not about a page** — `--late` prints the `y=` it measured at on every line, because from `y=0` alone three park pages Cloudflare scores 0.98 came back 0.0001, 0.0002 and 0.0002, the block that grows sitting four screens below the first one; it now measures the top and just under the biggest growth (1.3421 on Islands of Adventure at `y=3346`), and says so in words when nothing scored at any position it tried. **Proving a fix needs `pnpm measure:cls --late`**, not CPU throttling: the same page under the same 4× throttle measured 0.000 and 0.088 in two consecutive runs, while `--late` (shell now, streamed tail 1.5 s later, nothing throttled) reproduces Cloudflare's 0.538 for the glossary page to within 0.005, every run. The harness also sends a real `x-forwarded-for` now: from 127.0.0.1 `/api/nearby` geolocates nothing and every run settled on the nearby card's short empty state, which is how its placeholder got tuned backwards by 683 px. **And it is measured against `pnpm build && pnpm start`, at `localhost`** — both halves, because a run against `next dev` or against `127.0.0.1` reports a confident 0.0000 and looks exactly like a page with nothing wrong. `next dev` injects the stylesheet through JavaScript, so the JS-off pass (this script's whole model of the first paint) renders **unstyled** markup and every row it prints is Tailwind that had not arrived — one park page came out 8695 px "first" against 4408 px settled. And `next dev` answers **403** for `/_next/static/chunks/*` when the origin is `127.0.0.1`, which was the script's own default base: every chunk fails, the page never hydrates, and three consecutive runs graded a park page with no client JavaScript in it at all. Both are now refused rather than graded — `assertMeasurable` aborts on a failed `/_next/` subresource and on a JS-off body still sitting in the browser's serif default — and the default base is `localhost`. Two more things the dev server cannot show you: it flushes the whole document in one go, so every Suspense boundary resolves before the first paint, and its API responses are not the ones a phone waits on.
