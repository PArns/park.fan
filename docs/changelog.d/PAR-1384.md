### Parkys Tagestipp steht nur über seiner Stufe, „nichts zu sagen“ hält fünf Minuten

`tipAgreesWithLevel` (`lib/assistant/parky-tip.ts`) vergleicht jetzt die Stufe selbst, wenn der
Tipp sie mitbringt (`crowdLevel`): Ein Satz für „hoch“ stand bisher über „extrem“, weil beide
„Lieber nicht“ heißen. Ohne `crowdLevel` bleibt es beim Vergleich der Urteile. Die API schlüsselt
den Tipp außerdem nach Status und Stufe aller Tage, die der Satz liest, und schreibt ihn neu,
sobald sich ein Nachbartag bewegt, den er empfiehlt.

Das Tipp-Relay (`app/api/parks/[...path]/route.ts`) reicht `today` an die API weiter, statt es nur
als Cache-Schlüssel zu führen. Ein `today`, das nicht das heutige Datum des Parks ist, beantwortet
die API mit einem 204 und `no-store`; das Relay hält diesen 204 nirgends (`mayKeepNoTip`). Vorher
konnte eine Anfrage mit dem morgigen Datum um 23:58 den heutigen Satz („morgen …“) bis zu einem Tag
unter der URL von morgen bei Vercel ablegen.

Jeder andere 204 bekam die Fenster des Tipps: einen Tag bei Vercel bis zum nächsten Klingeln, eine
Stunde bei Cloudflare und im Browser. Übrig sind ein verbrauchtes Budget, ein gescheiterter oder
abgelehnter Aufruf, die sich im Lauf des Tages erledigen. Der 204 hat jetzt sein eigenes Fenster,
fünf Minuten überall (`PARKY_TIP_NONE_WINDOW`, `PARKY_TIP_NONE_SECONDS` in
`lib/api/cdn-cache-headers.ts`), und `useParkyDayTip` hält ein leeres Ergebnis ebenso kurz. Die
Regel in `next.config.ts` kann einen 204 nicht von einem 200 unterscheiden und trägt deshalb das
kürzere Fenster: Unter `next start` wird ein Tipp alle fünf Minuten neu gefragt, auf Vercel gilt
das Fenster des Handlers. `pnpm test:edge-windows` prüft das. `NO_STORE` setzt jetzt auch
`Vercel-CDN-Cache-Control`, sonst nahm ein Fehler unter einer geklingelten Route Vercels Tag aus
der Regel.

Im Chat nach einem Tipp-Klick liest die API Parkys Satz selbst aus ihrem Cache; den Satz aus dem
Browser nimmt sie an, verwendet ihn aber nicht mehr als Parkys eigene Worte.
