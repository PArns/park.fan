## Known Trade-offs / Open Items

0. **Backend re-slugs kill indexed URLs (July 2026 incident)** — the API's umlaut transliteration change (`bruhl` → `bruehl`, `gunzburg` → `guenzburg`) 404ed every indexed Phantasialand/Legoland-Deutschland URL; google.de stopped showing German pages and traffic skewed US. The GSC coverage export (2026-07-06) showed **2,388 known 404s**: ~38 % cross-locale glossary slugs (legacy next-intl auto-alternates), ~25 % stale `_next/static` deploy chunks (harmless, ignore), ~19 % `/v1/*` (already redirecting), the rest relocated cities / renamed parks / the pre-`/parks` URL scheme. Fixed: `findRelocatedParkRedirect` 308s park/attraction URLs whose park slug exists under different geo segments (runs only after an API miss, duplicate slugs disambiguated by continent), `findTermByAnySlug` translates foreign-locale glossary slugs, plus static 301s in `next.config.ts` (rules 6–10). The GSC "Duplicate, Google chose different canonical" report (135 pages) is ~95 % EN water-slide attraction pages — NOT a de→en language problem. **After any future backend slug change:** diff the GSC 404 export against `/v1/discovery/geo`, add redirects, then GSC URL inspection → "Request indexing" on the top pages. hreflang itself is correct site-wide — language swaps on google.de only work while the localized URLs actually resolve. Open backend bug: `universal-studios-hollywood` exists under both `bull-creek` and `los-angeles` in the geo structure (duplicate sitemap entries).
1. ~~Hub + attraction pages not in sitemap~~ — **revisited July 2026**: SERP checks showed the long-tail lives exactly there (queue-times/wartezeiten.app ride pages rank for "taron wartezeit"; country overviews rank for "freizeitparks deutschland"). Hubs are now in `/sitemap.xml` (multi-park cities only), attractions in the lean `/sitemap-attractions.xml`. Remaining upside: intent-specific park sub-pages (`/wartezeiten`, `/crowd-calendar` as real URLs instead of sections) — competitors rank each intent separately; that's a feature, not a tweak.
2. ~~Park page first HTML had no attraction names/links and no best-days text~~ — **fixed July 2026**: the attractions tab's pre-mount state is now the server-rendered `AttractionWaitOverview` (every attraction name + link + snapshot wait/status, per-land grouping, park summary, visible "Datenstand" timestamp), and the best-days section + least-crowded FAQ seed from the data-cached calendar (`getBestDaysCalendarSeed`, timeout-guarded so a cold fill never blocks TTFB; the visible answer and the FAQPage JSON-LD share one derivation). Client behavior (5-min live poll, `useLoadLast` deferral) unchanged. **Kept deliberately:** `PARK_REVALIDATE` = 1 day — crawled wait values are up to a day old and labelled with their "Datenstand"; shortening the window would re-create the data-cache write volume (see caching-strategy). If fresher crawled values are ever needed, the lever is the backend `revalidateTag('parks')` webhook, not a shorter TTL.
3. **`error.tsx` is a soft-200 for non-maintenance errors** — client error boundaries can't export metadata; the failing route itself returns HTTP 500, so impact is minimal.
4. **Maintenance flow** — `/maintenance` is noindex and auto-recovers via a 15 s health poll (`components/maintenance-page.tsx`). Crawlers hitting a failing route during an outage get HTTP 500 (retry-later semantics).
5. **Blog pagination** — not yet needed (`BLOG_POSTS_PER_PAGE`); when added, use path-based `/blog/page/[n]`, not query params.
6. ~~A rename stayed published at the dead path for days~~ — **fixed July 2026 (backend)**. Measured on production: `sitemap-attractions.xml` still listed **546 URLs** under `attractiepark-toverland` / `magic-kingdom-park` / `disneys-hollywood-studios` — every one a 308 — while the API's own `/v1/sitemap/attractions` had been correct for days, so the three renamed parks had **no valid attraction entry in any sitemap at all** and the daily IndexNow run kept submitting the redirects. Cause: nothing ever revalidated the frontend's `geo` tag. The chain is Cloudflare (`s-maxage=86400` + 48 h SWR on the API response) → Next Data Cache (24 h) → the sitemap route's own ISR entry, whose `expire` is effectively infinite, so it serves stale until something busts it. `ParkRenameService.handlePathChange` now POSTs `/api/revalidate` with `geo` + `parks` + `attractions`. **`geo` had never been revalidated by anything** — only `parks`/`attractions` (children-metadata) and `best-days:*` (cache warmup) were wired up.
7. **Duplicate park records produce duplicate content (open, backend data)** — two parks exist twice in the API with different geo, so both paths render the same park, both self-canonicalize and both sit in the sitemap:
   - `universal-studios-hollywood` — the real record is in `los-angeles` (34.137 / −118.356); `ef48df35…` sits in `bull-creek` at the placeholder coordinate **28.0 / −81.0** and still carries 29 attractions ⇒ ~1 050 duplicate locale URLs.
   - `universal-islands-of-adventure` — the real record is in `orlando`; `9500e2b7…` sits in `tampa` with **0 attractions** (a thin, empty park page × 6 locales).
     (`disneyland-park` under Paris _and_ Anaheim is legitimate — two different parks; the city is in the title, so they disambiguate.) The fix is merging the records upstream; hiding them frontend-side would only mask the data bug.
8. **Duplicate attraction rows make attraction URLs non-deterministic (open, backend data)** — the park detail runs `deduplicateEntities` (by **name**, preferring `OPERATING`, then coordinates), the sitemap endpoint does not. So a park holding two rows named "Alice in Wonderland" (`alice-in-wonderland`, `alice-in-wonderland-2`) embeds only the dedup winner, and the _other_ slug 404s on the page while still being listed. On top of that `getAttractionPaths`' variant rule drops `x-2` whenever `x` is listed — which inverts the pick more often than not. Measured: **123 such pairs**; of 40 sampled base slugs the sitemap keeps, **22 were 404** (⇒ ≈400 hard 404s across 6 locales, plus the working `-2` pages excluded from the sitemap entirely); 2 of 18 probed pairs 404 on _both_ slugs. No fix is possible on the sitemap side: the tie-break reads **live queue status**, so which URL resolves can change from day to day — coordinates predicted the resolving slug in only 5/18 cases. The real fix is merging the duplicate rows upstream so one name maps to one row.
9. **No `lastmod` in the sitemaps** — deliberate for now: `/v1/discovery/geo` exposes no per-park timestamp (only a top-level `generatedAt`), and Google discounts a `lastmod` that is identical across thousands of URLs. Prerequisite for adding one is a real `park.updatedAt` in the geo structure.
10. ~~Blog tag pages advertised five 404s as their hreflang alternates~~ — **fixed July 2026**. Tag slugs are translated with the post (`wartezeiten` / `wait-times` / `tempi-di-attesa`), but the alternates reused _this_ locale's slug for every locale, so each of the ~151 tag URLs pointed at five non-existent pages plus a dead `x-default` — a cluster Google drops wholesale. Tags carry no `translationKey`, but every translation of a post lists the same tags in the same order, so `buildTagAlternates` (`lib/blog/tags.ts`) zips the arrays by position, then verifies the mapped slug actually has a page. 146 of 164 tag entries now resolve across all six locales; the remainder are posts that exist in fewer locales, and ambiguous mappings are dropped rather than guessed. The convention is documented in [content/blog/README.md](../../content/blog/README.md#4-categories--tags) — **reordering tags in one language silently breaks it**. Categories are unaffected (`news` / `guides` / `behind-the-scenes` are the same path in every locale).
11. ~~`BlogPosting.author` published the registry key~~ — **fixed July 2026**: `author: patrick` in frontmatter is a key into `content/blog/authors/`, but the JSON-LD took it verbatim, so the byline Google reads said `"patrick"` and carried no url/avatar/bio. It now runs through `resolveAuthor` like the visible page, links `author.url` to the on-site profile (`/{locale}/blog/authors/{key}`) and moves the personal site into `sameAs`.
12. ~~A JSON-LD reference that left its own `<script>` arrived untyped~~ — **fixed August 2026**. Search Console flagged the wait-time calendar's `Dataset` with „Ungültiger Objekttyp für Feld `spatialCoverage`": the value was `{"@id": "…/hansa-park"}`, and the `AmusementPark` stub it was written against sits in `ParkSubPageStructuredData`'s `@graph`, one `<script>` block over. A consumer that reads one block at a time has an object with no type, and `spatialCoverage` wants a `Place`. Six more references had the same shape and were silent only because nothing validates the types they sit on: `WebSite.publisher`, `WebPage.isPartOf` (twice), `WebPage.mainEntity`, `Dataset.creator` and every `Observation.observationAbout` on a park page — the last pointing at ride ids declared in the sibling script. All seven now state their type; `about` in `ParkSubPageStructuredData` stays bare because its target is in the same `@graph`. The descriptions did not move: the park's address, hours, photos and socials still live only on the park page, since restating them on 24,000 calendar URLs is one entity written 24,000 times.
13. **The trip planner had no inbound link that carried any intent (Sept 2026)** — audited page by page against a running build. What was already right: six locales each with `canonical` plus seven `alternate` links including `x-default` (the `alternates` trap — Next replaces the whole object at the nearest declaring segment — did **not** bite here), one `<url>` per locale in `sitemap.xml` with full `xhtml:link` alternates, titles 50–58 and descriptions 146–157 characters in every language, `index, follow`, an OG image that renders (200, `image/jpeg`, 14.8 KB), a BreadcrumbList, and 2,002 (de) / 2,157 (en) words of server-rendered editorial text under one `<h1>` and seven `<h2>`s, with 69 internal links out. What was missing was inbound: **the only three links to it were site chrome** — the header nav, the burger and the footer — so nothing pointed at it from the pages that carry both the intent and the authority. `ParkPlannerLink` now sits in the header of every park page and every wait-time calendar, with the **park name in the anchor** ("Tag im Phantasialand planen"): 212 pages all saying "Tagesplaner" would be 212 pages saying the same four words. Second gap, same audit: `/llms.txt` listed six "Start here" entries and the planner was not one of them — on the one document an agent reads to learn what the site offers. Third: 26 of 30 `<img>` on the page had no `alt`, six of them polaroids whose localized alt text was sitting in the media database unused, under a container carrying `aria-hidden="true"` — which would have made any alt text useless to a screen reader while still helping Google Images.

    **Deliberately not done, with reasons.** No `lastModified` on the sitemap entry: a `lastmod` is [observed, never stamped](sitemaps.md#lastmod-observed-not-stamped), the honest value here is a git date that is not available at request time, and a `new Date()` is a build stamp — one identical value everywhere is exactly what gets a sitemap's lastmod discounted, taking the glossary's and the blog's real dates down with it. No `SoftwareApplication` JSON-LD: without ratings Google shows no rich result for it, and this repo does not add schema in order to win one that does not exist (the same reasoning that keeps `FAQPage` where it already is and adds it nowhere new). `changeFrequency` and `priority` stay although Google ignores both — they are on every entry of this sitemap, so removing them is a site-wide decision rather than a planner one.

14. **OG cards are 700–900 KB PNGs** — fine for Google/Twitter, but above what some messengers (WhatsApp) will fetch for a link preview. Lowering the render quality in `app/api/og/[...path]/route.tsx` is the lever if link previews matter.

## Quick Checklist After Major Changes

- [ ] New page types: `generateMetadata` with canonical + hreflang (use `SITE_URL` + `generateAlternateLanguages`), OG image, sensible robots.
- [ ] noindex pages must NOT be added to `app/sitemap.ts`.
- [ ] New locale-prefixed routes reachable via internal links (header/footer/breadcrumbs).
- [ ] Structured data passes the Google Rich Results Test.
- [ ] A JSON-LD reference that points into another `<script>` on the page carries `@type` as well as `@id` — see item 12. Inside one `@graph`, `@id` alone is enough.
- [ ] Titles < ~60 chars, descriptions ~150–160 chars (see `seo.*` in `messages/*.json`). Templated pages don't need manual checking — park/geo-hub titles run through `fitWithin(MAX_TITLE_LENGTH, full, short)` (`lib/utils/metadata.ts`), which falls back to the `titleTemplateShort` key when a long name would overrun. New templated page types should add a short variant and do the same.
- [ ] Don't block crawlable assets in `app/robots.ts` (especially `/api/og/`, `/_next/`).
