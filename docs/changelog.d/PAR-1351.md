### Jeder Build liest die Reise-Regionen frisch von der Edge

Nach einem API-Deploy, der die Antwort einer Region änderte, lieferte Cloudflare
`/v1/trip-regions/:region` bis zu 26 Stunden lang alt aus (ein Tag `s-maxage`, zwei Stunden
`stale-while-revalidate`), und die API kann Cloudflare nicht leeren. Am 15. November war Orlandos
Kopie an der Edge rund 18 Stunden alt und hatte kein `weather`, keine `hotels` und keine
`ticketMarkets`. Jetzt hängt jeder Server-Read einer Reise-Region-Route, der Relay
(`app/api/trip-regions/[...path]/route.ts`) eingeschlossen, die Build-Nummer als `v` an
(`tripRegionApiUrl` in `lib/trip-regions/api.ts`, aus `build-info.json`), also liest jeder Build
eine eigene Edge-Kopie. Die API nimmt `v` auf allen Reise-Region-Routen an und muss vorher
ausgerollt sein. Tags und Revalidate-Zeiten des Data Cache bleiben, wie sie waren
([Reise-Regionen](../features/trip-regions.md#data)).
