### Tagesplaner: Der Fit-Assistent nennt eine gepinnte Bahn, die nicht mehr passt, für sich

Seit PAR-1452 gibt die API eine gepinnte Bahn nur noch auf, wenn keine ungepinnte Bahn Platz machen
kann, und nennt sie in `fit.pinnedMissed`. `FitAnswer` (`lib/planner/optimize-remote.ts`) liest das
Feld; ein älterer Server ohne das Feld liest sich als leere Liste. Im Ergebnis-Schritt von
`PlannerFitAssistant` steht eine solche Bahn jetzt in einem eigenen Kasten mit Pin, „Diese gepinnte
Bahn passt nicht mehr in den Tag“ (`planner.fit.resultPinnedOut`, sechs Sprachen), über „Bleibt
draußen“. Getrennt wird in `fitLeftOut` (`lib/planner/fit.ts`), `pnpm test:planner-fit` prüft es.
Vorher standen beide Gruppen in einer Zeile, und wer eine Bahn gepinnt hatte, sah nicht, dass auch
das Abwählen anderer Bahnen sie nicht zurückholt.

Phantasialand am 5. Dezember 2026, ein Block von 12 bis 20 Uhr, Taron, Black Mamba und F.L.Y.
gepinnt: Black Mamba und Crazy Bats passen in den Vormittag, Taron und F.L.Y. auch ohne jede
ungepinnte Bahn nicht. Der neue Kasten nennt diese zwei, „Bleibt draußen“ die anderen sechs.

Zwei Antworten vergleicht das Web nicht: Jeder Tipp im Assistenten fragt die API und zeigt deren
Antwort. Vorher und nachher gibt es nur innerhalb einer Antwort (`before`, `after`), gerechnet vom
Server.
