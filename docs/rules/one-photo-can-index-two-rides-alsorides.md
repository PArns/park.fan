# One photo can index two rides (`alsoRides`)

One standing rule. It is indexed from the repo's [`CLAUDE.md`](../../CLAUDE.md), which carries the rule in one line and links here for the reasoning, the measurements and the counter-examples.

the API lists Winja's Fear/Force and YOY Chill/Thrill as two attractions each, but the park built one structure and the photo is genuinely of both. `ride` holds one slug, so these used to be stored as two byte-identical files — and when the media migration removed the duplicate, the second ride silently lost its only picture (no error: nothing re-checks whether a ride still has one). `alsoRides` names the further rides a photo answers for, matched by `getRideImages`/`getRideImage`/`searchMedia` and by the `ride-card` uniqueness audit; every slug is validated against the park's attractions, so the next typo is a build warning instead of another blank ride page. It is the `ride` counterpart to `roles` carrying two entries (`symbolica.jpg` is `park-background` **and** `ride-card`) — and not a licence to reuse: the photo must be a fair card for every slug named. See [public/media/README.md](public/media/README.md) and [media database](docs/features/media-database.md).
