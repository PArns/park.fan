# Data and API rules

These are the standing rules for this area, moved out of `CLAUDE.md` so that a session reads an index first and opens only the pages its task needs. The wording is unchanged; each rule links on to the document that carries the measurements behind it.

## Parks we cannot read (REQUIREMENT)

Hansa-Park publishes wait times only in its own app on the park WLAN, so no number will ever arrive for it — and a park with no source is **indistinguishable from a park shut for the night** in the payload (at 03:00 every park has zero rides operating and empty `queues`). So never derive it: the API's curated `liveWaitTimes` (`{available, reason}`) is the only signal, read through `noLiveWaitTimesReason()` / `hasReadableWaitTimes()` in `lib/utils/live-wait-times.ts`, which treats an absent field as available so older/cached responses keep behaving as before. It is **not** a freshness check — a feed that went quiet an hour ago stays `available: true`. Left alone, the page fills the gap with the shape of a quiet park: 82 of 82 rides "running" at `very_low`, Ø 0 min, plus an ML forecast built on zero observations. Crowd badges need no special case (the API sends `unknown` → "keine Prognose"); the listing surfaces **strip** `crowdLevel`/`averageWaitTime`/`operatingAttractions` at the projection boundary rather than shipping the flag, because the poll re-downloads its nine fields per park every 5 min and this one never changes. And the two surfaces that say so out loud — the notice and the overview's summary line — carry **`data-nosnippet`**, as prevention rather than repair: they are the most quotable prose on the strongest page the site has, and a result answering „Hansa-Park Wartezeiten" with „Keine Wartezeiten verfügbar" is a result nobody clicks. Google is **not** doing that — checked 2026-08-30, the head query renders the meta description verbatim — but a snippet is picked per query, so the guard is cheap and the alternative is not: `noindex` has no per-element form and the page-level one would drop the park, while `data-nosnippet` keeps the sentence crawled, ranked and visible to the reader and only bars it from the description. Honoured on `div`/`span`/`section` alone, which is why the summary line wraps a `<span>` rather than tagging its `<p>`. Two things it does not touch, both in that same result: title, meta description and the FAQ still promise live wait times there (a ranking decision on the biggest page), and the „vor 6 Tagen" in front of the snippet is the page dating **itself** — „Heute, Sonntag, 30. August 2026, hat der Hansa-Park … geöffnet" stands in the FAQ block and again in the FAQPage JSON-LD, there is no `datePublished`/`dateModified`, so Google shows what it read on its last crawl. See [parks without wait times](docs/api/parks-without-wait-times.md).

## A ride out of season is closed, and is not one of the park's rides today (REQUIREMENT)

Phantasialands Schlittschuhverleih läuft im November, Dezember und Januar — und stand am 21. August auf der Parkseite als **geöffnet** bei `very_low`, während seine eigene Seite **geschlossen** lieferte, aus derselben Datenbankzeile. Schuld war der optimistische Fallback der Ride-Liste: kommt keine Queue-Zeile an und ist der Park offen, gilt die Bahn als offen. Der ist für einen Feed gedacht, der stehengeblieben ist — über eine Eisbahn im August meldet niemand etwas, weil es nichts zu melden gibt, und aus dieser Stille wurde eine geöffnete Attraktion. Die Regel liegt jetzt in `statusWithoutLiveData` (API). `isCurrentlyInSeason` hat **drei** Werte und der dritte ist der Punkt: `false` schließt, `true` ist offen, **`null` verhält sich exakt wie vorher** — es heißt „saisonal, sonst nichts bekannt" und darf keine Bahn verstecken, die wir bloß noch nicht verstanden haben. Dort sitzen die meisten: der Detector nennt für alles unter 330 Beobachtungstagen bewusst keine Monate. Also überall `!== false`, nie `=== true` (`lib/utils/season.ts`). Eine Live-`OPERATING`-Zeile schlägt trotzdem alles: sie ist eine Beobachtung, die Saison eine Beschreibung von Vergangenem. Dasselbe gilt für den Zähler: **„12 von 45 geöffnet"** ist eine Aussage darüber, wofür man sich heute anstellen kann, und eine Bahn, die vor November gar nicht aufmachen kann, gehört weder zu den 45 noch zu den 33 geschlossenen. Denselben Satz rendern **vier** Quellen, drei davon SQL über den ganzen Katalog ohne je eine Zeile zu laden — dafür gibt es `attractionIsOutOfSeason()`, den SQL-Zwilling der TS-Regel, nach dem Vorbild von `scheduleRowSpeaksForToday()` und gegen einen echten Postgres über alle 300 Spaltenkombinationen geprüft; handgeschriebener Zwilling, also ändert man beide Hälften oder keine. Auf dieser Seite blendet die **Pre-Mount-Übersicht** die Bahnen jetzt genauso aus wie die Karten daneben — sie ist das einzige Attraktions-Markup ohne JavaScript und listete sie direkt unter dem Zähler, der sie weglässt —, und der Badge sagt **„Nur im Winter"** statt zweimal „Winter" in zwei Deckkraftstufen. Strukturierte Daten behalten sie: `containsPlace` sagt, was der Park enthält, und das ist ganzjährig wahr. Ist der Detector schlicht im Unrecht (lange Umbaupause sieht von außen aus wie eine Saison), ist das eine Kuration unter `/admin/attractions/<id>` — **Saisonal** und **Betriebsmonate**; existiert die Bahn gar nicht mehr, ist daneben der **Status**. See [seasonal attractions](docs/api/seasonal-attractions.md).
