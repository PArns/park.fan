# A version is a unit of communication, not a build artifact (REQUIREMENT)

One standing rule. It is indexed from the repo's [`CLAUDE.md`](../../CLAUDE.md), which carries the rule in one line and links here for the reasoning, the measurements and the counter-examples.

this site deploys continuously, so **a merge is not a version** and nothing bumps `package.json` per pull request — a version is drawn when there is something to tell people, which is why it is the PO who cuts one, at a cycle boundary or when enough has accumulated, no more often than weekly and no less often than monthly. The number follows what a **visitor** can see: **MINOR** (`x.Y.0`) once at least one new visible capability has landed since the last cut — a page, a flow, a behaviour somebody would notice; **PATCH** (`x.y.Z`) for a bundle of fixes and small improvements with no new capability; **MAJOR** is reserved for a relaunch and is expected to stay unused, because a website has no breaking change to offer the people reading it. Two files carry releases and they are not two copies of one thing: `docs/changelog.md` is the **internal** log, German, per pull request, naming components and measurements, and `content/changelog/<version>.md` is the **public** entry, English, written by hand from those sections when the version is cut. Nothing parses one into the other, and nothing should — the internal prose is written for whoever touches the code next, and publishing it verbatim is how a changelog turns into a commit list. The public entry says what changed for a visitor, prefers a number to an adjective, and gets a screenshot for a highlight, stored in `public/media/changelog/` under the ordinary sidecar rules ([media database](media-database.md)) with `tags: ["diagram"]` and no `park`/`ride`, because a picture of our own interface is not a photograph of a park. **A blog post is never a release**: it ships in the same build and it is content, not product, so it belongs in the feed and never in `content/changelog/`. The page itself is English only and lives at `/en/changelog`; `/changelog` and the five other locale spellings are 301s in `next.config.ts`, which is where they have to be, because `redirects()` runs before the proxy and the proxy would otherwise resolve the bare path against Accept-Language. Authoring contract: [content/changelog/README.md](../../content/changelog/README.md).
