# Media database (REQUIREMENT)

One standing rule. It is indexed from the repo's [`CLAUDE.md`](../../CLAUDE.md), which carries the rule in one line and links here for the reasoning, the measurements and the counter-examples.

every image — park, ride, blog, diagram — lives in ONE filesystem-backed database at `public/media/<collection>/`, with a `<name>.json` sidecar per image. **A collection is storage, the sidecar is the index:** nothing queries by folder, so a Halloween photo of Troy sits in `toverland-halloween` and still answers `getRideImages('toverland','troy')`. Never infer park/ride/role from a filename or folder. Read from `@/lib/media` (structure + search), `@/lib/media/text` (localized alt/caption — 37 KB, import only where text is rendered) and `@/lib/media/hero` (**the only client-safe one** — importing `@/lib/media` into a Client Component ships the 107 KB catalog). Image URLs carry `?v=<content hash>` because retargeting a focal point rewrites a crop's bytes at an unchanged URL; `images.localPatterns` in `next.config.ts` is what permits that query. `focus` is one point per image driving BOTH the CSS `object-position` on every card/background AND the offset the build-time 16:9/4:3/1:1 crops are cut at. **A photo that is not ours carries its attribution on the image**, not in a source list somewhere else: `needsAttribution()` is true as soon as `credit.author` is set to anybody but `OWN_PHOTO_AUTHOR`, and `<PhotoCredit>` (`components/media/photo-credit.tsx`) renders `getCreditLine()` as a badge in the bottom-right corner of the picture, so it needs a `relative` parent. The first case was the Unsplash cover of the Heide Park guide, which is also why `unsplash` is a `MediaLicense` value of its own: the licence permits commercial use, and `unknown` would have understated rights that are established. Authoring contract: [public/media/README.md](public/media/README.md); full docs: [media database](docs/features/media-database.md).
