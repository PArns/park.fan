# The guide page teaches the real cards with the ride's real numbers (REQUIREMENT)

One standing rule. It is indexed from the repo's [`CLAUDE.md`](../../CLAUDE.md), which carries the rule in one line and links here for the reasoning, the measurements and the counter-examples.

`/{locale}/{howto-segment}` (`app/[locale]/how-park-fan-works/`, localized slug in `lib/howto/segments.ts`, the old `/howto` 301s per locale, bare `/howto` deliberately left to the middleware so it lands in the reader's language) answers „was macht diese Seite, was ein Wartezeiten-Feed nicht macht“, so every block renders a **production** component — `AttractionCard`, `AttractionTypicalWaits`, `RopeDropCard`, `ParkCalendarDay`, `NoLiveWaitTimesNotice` — and every figure in it is a value the API actually returned, dated in `_fixtures.ts`. A redrawn lookalike defeats the exercise and starts lying at the first restyle; an invented number is worse, because the block next to it links to the ride's own page. **Audit before you claim**: `AttractionTypicalWaits` prints the weekday's **P90** above each bar and no measured-day count (its hint names the _window_, not the sample size), and **no surface anywhere puts sample days next to a ride** — `ParkStatsAttractionsCard` renders rank/ride/(now)/P50/P90, and the count exists only in the stats section's subtitle, the `Tage` column of the by-month and by-weekday cards, and the blog's `ride-waits-widget`; four sentences claiming a per-ride column on the park page shipped in German and were translated into five more languages before anyone read them; `typicalWaitThisHour`/`currentVsTypical` exist on the payload and are rendered **nowhere**; the calendar reaches a year out only for year-round parks, while a seasonal one returns CLOSED past its published season; and „früh kommen“ is a per-ride finding, not a rule — Taron's day is flat (60/60/54/53/59 by hour) where Chiapas climbs 22 minutes. The thresholds are visible in one park: Colorado Adventure saves 40 off a 50-minute peak and gets no rope-drop tip against the ≥60/≥45 gate. **A displayed wait time is always a multiple of five** — parks post them that way, so every raw observation is, and what breaks it is the maths on top: `PERCENTILE_CONT` interpolates between two stored values and `AVG()` across days blurs the rest, which is how the hourly table printed 51, 53 and 47. The API rounds on the way out and `roundWaitTo5` (`lib/utils/wait-time.ts`) does it again at render, so a surface is right whichever build answers. **Round only what is displayed**: a crowd ratio, a ranking, a colour tier and the pick of a ride's peak hour all read the raw value, or five-minute buckets invent ties the data does not have — rounding first moved Wodan's peak from 12:00 to 11:00 and broke a test. And a **difference** is not a wait time: `roundWaitTo5` floors everything under 2.5 to zero because no queue is −15 minutes long, so pointing it at the attraction card's trend delta deleted the whole falling half of the scale and every shrinking queue on every park page rendered „stabil" — visible on the guide itself, where Black Mamba sat at a grey „Stabil" under a caption saying its queue was being worked off. Signed deltas go through `roundWaitDeltaTo5`. Two live blocks are exceptions to the frozen-fixture rule (`LiveHourlyProfile`, `LiveTopAttractions`): where the point is „das läuft gerade", a frozen copy is the wrong exhibit, and the prose beside them names no figure they render. Two fixture anchors: the queue history, best-visit slot and rope-drop instants come from `getServerNowMs()` because a card's sparkline stretches its axis to the reader's clock and a hard-coded date decays into a flat week-long tail, while the rope-drop instants are wall-clock times in the **park's** zone. Motion follows `use-menu-reveal`'s split plus **no ScrollTrigger**: `WaitScaleBar` is a server-rendered `<figure>` whose geometry is three CSS custom properties, an `IntersectionObserver` picks the step and GSAP only tweens between two readings. Two traps the visuals cost: `Sparkline` fits each instance to its own max, so two charts meant to be compared need the shared `yMax` prop or the flat one is drawn as dramatically as the steep one; and the wide decorative layers (the wait-time display's glow, `Ambience`) must be clipped with **`overflow-x-clip`**, never `overflow-hidden`, which would make the element a scroll container and stop the sticky figure pinning. Structured data is Article + Breadcrumb + `FaqList`'s `FAQPage`, never `HowTo` — but the two are dead for **different** reasons and only one of them is a reason to remove anything. `HowTo` was deprecated outright (Sept 2023). `FAQPage` still validates and still describes the page truthfully; what ended is the SERP feature, and not only for the health and government sites the Aug 2023 restriction named: **Google retired FAQ rich results for every site on 2026-05-07**. So the markup stays where it is (it costs nothing, and it is an honest description of a block that really is a list of questions), and no new page gets `FAQPage` _in order to_ win a rich result, because there is none to win. Do not claim an AI-citation benefit for it either — nobody has measured one. Genuine user-submitted Q&A is `QAPage`, which is a different type for a different thing. All six locales ship the guide as a full `content/<locale>.tsx` with localized chapter ids, the same per-locale-module convention as `fancast` — so an edit lands six times, and two greps guard it: `CHAPTERS` must match the rendered `<SectionShell id= index=>` calls exactly, and each file's `locale=` prop on the two live blocks must be its own.
